# Kaizen help

Show this reference, then offer to start with `/kaizen` on the user's own process.

| Command | What it does | Use it when |
|---------|--------------|-------------|
| `/kaizen [lite\|full\|ultra]` | Process engineer mode: go see, map, remove waste, fix the root cause, then automate what is left | You want to automate, speed up or add AI to any workflow |
| `/kaizen-map` | SIPOC, step table with times, swimlane, and a BPMN 2.0 file | You need to see the process as it really runs |
| `/kaizen-waste` | Waste walk with the eight wastes, ranked by hours lost per week | You are busy but nothing moves, and want to know what to fix first |
| `/kaizen-why` | Root cause analysis: 5 whys with evidence, fishbone, corrective and preventive actions | Something went wrong, or keeps going wrong |
| `/kaizen-roi` | Business case with the cost of errors, payback, break-even and stop criteria | You need to decide or convince with numbers |
| `/kaizen-sop` | One-page procedure, checklist, error-proofing, control plan | You want an improvement to last |

**Levels of `/kaizen`**

- **lite**: does what you ask, with three lines of kaizen check first.
- **full** (default): the whole method, as a one-screen kaizen sheet.
- **ultra**: also questions whether the process should exist, and requires real data.

**The ladder**, in order: eliminate, combine or rearrange, simplify, error-proof, automate with rules, automate with AI, keep human.

Stop the mode with "stop kaizen".
